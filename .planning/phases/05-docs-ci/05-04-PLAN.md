<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → npm registry | Publish job sends package artifact + OIDC token to npmjs.org |
| GitHub OIDC → npm provenance | id-token:write permission mints an OIDC token that npm uses to create a signed source→artifact attestation |
| secrets.NPM_ACCESS_TOKEN → npm publish | Scoped npm token authorizes the publish; least-privilege (publish-only scope recommended) |
| PR branch code → ci.yml execution | Untrusted PR code runs lint + test in an ephemeral ubuntu-latest container |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Tampering | Supply-chain / unpinned GitHub Actions | mitigate | SHA-pin both actions to commit SHA (D-09): checkout@11bd71901... and setup-node@49933ea...; tag refs (@v3/@v4) are mutable and could be moved to malicious commits |
| T-05-04-02 | Elevation of Privilege | Accidental/unauthorized publish on push to main | mitigate | Replace push:main trigger with release:published (D-08); a stray merge to main no longer triggers publish; only an explicit GitHub release event does |
| T-05-04-03 | Elevation of Privilege | Publish without lint/test gate | mitigate | Lint + test steps run BEFORE publish step (D-08); if either fails, the workflow exits and npm publish never runs |
| T-05-04-04 | Information Disclosure | NPM_ACCESS_TOKEN secret exposure | mitigate | Token only in NODE_AUTH_TOKEN env on the publish step (scoped); permissions: contents: read prevents write access to repo; id-token: write is job-scoped, not workflow-scoped |
| T-05-04-05 | Repudiation | Artifact origin unverifiable | mitigate | npm provenance attestation (--provenance flag + id-token: write) generates a signed SLSA attestation linking the published artifact to this specific GitHub Actions run and commit SHA; shows "verified" badge on npmjs.com (D-10) |
| T-05-04-06 | Elevation of Privilege | workflow_dispatch bypasses release guard | accept | workflow_dispatch is retained as emergency/recovery fallback (D-08); the lint+test gate still runs before publish; risk is low because a developer must explicitly trigger it with repo write access; documented in workflow comments |
| T-05-04-07 | Denial of Service | PR from fork triggers expensive CI | accept | ubuntu-latest runs are ~60s for lint+test; GitHub provides free minutes for OSS public repos; no secrets exposed to fork PRs (GitHub secrets are not available in fork PRs by default) |
</threat_model>
