<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumer JSX → Forge | App-supplied children, onSubmit callback, field names cross into Forge's tree-walker (untrusted shape, but same-origin app code — not network input) |
| browser DOM → form submit | Switching `<div>`→`<form>` activates native browser submission + native validation |

Forge is a headless client-side form library. It has no network calls, no auth, no persistence, no secret handling. The threat surface is limited to client-side behavior changes.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `<form>` default submit (GET to current URL) | mitigate | `onSubmit={control.handleSubmit(...)}` — RHF's handleSubmit calls `event.preventDefault()` internally, preventing an unintended native navigation/page reload. No `action`/`method` attributes are set (D-05 keeps surface tight), so there is no implicit endpoint. |
| T-01-02 | Information Disclosure | new fail-fast / wizard submit paths | accept | This plan's handlers pass form data only to the consumer's own `onSubmit` callback; no field values are logged, serialized to errors, or sent anywhere. No new disclosure vector. |
| T-01-03 | Denial of Service | `noValidate` default = false | accept | Native validation ON by default (D-06) is the documented/desired behavior (success criterion #1). No DoS surface; consumers opt out via `noValidate`. |
</threat_model>
