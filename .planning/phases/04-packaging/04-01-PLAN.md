<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem → npm registry | npm publish sends the tarball (built by prepack) to registry.npmjs.org; the NPM_ACCESS_TOKEN authenticates this operation |
| package.json author field → published manifest | Author metadata is public-readable by all npm consumers; anything written here is permanently on the registry |
| package.json publishConfig.registry → CI registry-url | If these two disagree, npm may publish to an unintended registry without error |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | package.json publishConfig.registry | mitigate | D-02: Replace GitHub Packages URL with "https://registry.npmjs.org" in publishConfig; Task 1 verifies via automated node assertion that the exact string is present. Both publishConfig and CI registry-url must agree — checked in Plan 02 verification. |
| T-04-02 | Information Disclosure | package.json author field | mitigate | D-09 explicitly prohibits auto-inserting a personal email into the public manifest. Task 1 acceptance criteria assert author has NO email field. |
| T-04-03 | Elevation of Privilege | NPM_ACCESS_TOKEN in CI | accept | The token is already present as a GitHub Actions secret (pre-existing CI config); Phase 4 does not change secret storage or scope. Phase 5 (CICD-03) owns SHA-pinning and publish gating — legitimate risk accepted for this phase. |
| T-04-04 | Tampering | Tarball contents via stale dist/ | mitigate | D-05: prepack script rebuilds dist/ fresh from source (rollup -c) before every npm pack / npm publish, preventing a stale or manually-poisoned dist/ from shipping. Verified in Plan 02 Task 1. |
| T-04-05 | Information Disclosure | Sensitive files in tarball | accept | files: ["dist"] is the sole include list (D-08: no .npmignore). npm auto-adds package.json, README.md, LICENSE. No .env, no credentials, no src/ in the tarball. Confirmed by npm pack --dry-run in Plan 02. |
| T-04-06 | Spoofing | Registry confusion (wrong registry receives publish) | mitigate | publishConfig.registry (Task 1) and CI registry-url already both read "https://registry.npmjs.org"; Task 2 PATTERNS.md confirms registry-url is untouched; Plan 02 verification asserts agreement. |
</threat_model>
