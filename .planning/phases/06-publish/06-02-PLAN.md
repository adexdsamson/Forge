## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Secret → CI env | NPM_ACCESS_TOKEN passed as NODE_AUTH_TOKEN; never echoed in logs |
| developer machine → npm registry | npm publish --dry-run validates locally; no credential transmission in dry-run mode |
| npm token → npmjs.com | Token must be Automation type; if it is a Publish/Read-only type, CI publish will fail post-release |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Elevation of Privilege | NPM_ACCESS_TOKEN (stale/wrong type) | mitigate | Task 1 human check: confirm Automation type + non-expired at npmjs.com before proceeding; rotate if needed (D-06) |
| T-06-02-02 | Information Disclosure | NPM_ACCESS_TOKEN in CI logs | mitigate | publish.yml uses ${{ secrets.NPM_ACCESS_TOKEN }} as NODE_AUTH_TOKEN — GitHub Actions masks secret values in logs automatically; do NOT echo the token in any script |
| T-06-02-03 | Tampering | Over-privileged token scope | mitigate | Use Granular or Automation token scoped to @adexdsamson/forge publish only; do not use a full-account token if avoidable |
| T-06-02-04 | Denial of Service | Publish before test gate | accept | publish.yml has lint + test steps that run before the publish step; cannot be skipped via normal flow; workflow_dispatch also runs gates (verified in research Q4) |
