<objective>
Fix React Native submit-button parity in Forge: when a user marks an RN button with
`forgeSubmit={true}`, Forge auto-wires its `onPress` handler to `control.handleSubmit`,
eliminating the redundant manual `onPress={handleSubmit(onSubmit)}` currently required.

Purpose: `onSubmit` on `<Forge>` is currently decorative on RN (onClick is inert on RN
components). This makes the web and RN DX diverge. The fix mirrors the existing
`data-wizard-nav` marker pattern already present in the child-walker.

Output: Three changed source files + one new test file + three updated doc files.
No version bump; no publish.
</objective>

From src/reactNative.ts:19-35 (getEventHandlerName — field inputs only, NOT for buttons):

  export const getEventHandlerName = (componentType: string): string => {
    if (!isReactNative) return 'onChange';
    switch (componentType) {
      case 'TextInput': return 'onChangeText';
      case 'Switch': case 'Picker': case 'Slider': return 'onValueChange';
      case 'CheckBox': case 'RadioButton': return 'onValueChange';
      default: return 'onChange';    // ← wrong for a press button
    }
  };
